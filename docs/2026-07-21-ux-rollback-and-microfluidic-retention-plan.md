# FluoColor 用户体验回退与微流控能力保留方案

> 文档状态：最终修改方案，尚未实施业务代码变更
> 审查日期：2026-07-21
> Git 旧版交互基线：`dd643eb`
> 当前工作区：存在大量未提交修改，禁止直接重置或清理

## 1. 本轮审查目标

本轮只回答一个问题：在保留微流控检测能力的前提下，如何恢复旧版简单、直接、易理解的用户体验。

审查范围包括：

- 旧版与当前的新建项目流程。
- 旧曲线模型库与当前分析模型库。
- 实验模板、载体布局、采集设备和分析模型之间的关系。
- 编辑、删除、发布、版本和归档逻辑。
- PG-Grid、比色/荧光光度处理、通用阵列结果页等新增能力是否值得保留。

Stitch 设计稿、Stitch 项目 ID 和页面生成记录不作为需求、代码或验收依据。

## 2. Git 与代码审查结论

### 2.1 旧版交互基线

大规模多模态领域重构开始前的可靠代码基线是 `dd643eb`。

与该基线相比，当前已跟踪文件的差异约为：

- 93 个文件发生变化。
- 新增约 15071 行。
- 删除约 3832 行。
- 当前工作区另有大量修改文件和未跟踪文件。

因此不应直接执行 `git reset --hard dd643eb`。直接回滚会同时丢失已经完成的 PG-Grid、Room 12、阵列结果、导出、光度分流和测试成果。

旧版应作为“交互行为参考”，而不是作为直接覆盖当前工作区的目标提交。

### 2.2 旧版已经具备的正确交互

旧版并不是功能空白，它已经具备以下合理设计：

- 新建项目直接填写项目名称、检测模式、分析方法、行列、分析物和图片，然后创建项目。
- 浓度单位读取系统设置中的可用单位列表并通过下拉框选择。
- 可靠范围输入实时限制为合法非负小数，并即时检查上下限关系。
- 标准曲线通过录入标准品浓度和选择候选函数进行拟合。
- 拟合引擎自动尝试多个函数和像素特征，并按 R² 从高到低排序。
- 曲线函数参数由系统计算，不要求用户输入 JSON。
- 曲线模型支持直接编辑名称和像素类型，也支持确认后直接删除。
- 实验模板支持直接编辑、直接删除和虚拟孔板布局。
- `InteractivePlateGrid` 已经能给孔位分配角色。

这些交互应作为本轮恢复工作的主要参考。

## 3. 当前设计的核心问题

### 3.1 新建项目被后台资源体系阻断

当前快速新建要求同时满足：

- 必须选择已发布模板。
- 模板必须处于可解析状态。
- 必须存在有效载体档案。
- 必须存在有效采集设备档案。
- 每个分析物必须绑定已发布分析模型。
- 模型必须匹配模态、协议、载体和采集设备。
- 所有样本位点必须填写样本编号。
- 必须已经选择图片。

`TemplateProjectFormState.canSubmit` 把上述条件全部变成创建按钮的前置门槛。这与旧版“填完本次实验信息即可创建”的体验完全相反。

### 3.2 分析模型表单直接暴露数据库字段

当前表单向用户暴露了：

- “科学身份”。
- “处理契约”。
- 处理器名称和版本概念。
- 参数 JSON。
- 模型文件名。
- SHA-256。
- 输入宽度和高度。
- 归一化 JSON。
- 训练数据版本。

这些属于系统内部、开发者或模型发布工具应处理的信息，不应由普通实验人员手动填写。

更严重的是，当前微流控检测协调器实际只调用 `StandardCurveQuantifier`。深度学习模型定义虽然可以保存，但量化阶段并没有对应的深度学习执行器，最终会退回仅信号结果。

因此当前界面要求用户填写了一套暂时不会被真正执行的专业参数。

### 3.3 采集设备档案没有解决真正的问题

当前采集设备档案要求用户选择或填写：

- 支持的检测模态。
- 兼容载体类型。
- 设备匹配说明。
- 光学模块名称。
- 固定装置或卡槽编号。
- 相机控制策略。

但代码审查发现：

- 设备匹配说明主要被编码为说明性 JSON。
- 光学模块名称当前主要被写入项目的 `lightSource` 和页面摘要。
- 固定装置编号主要用于展示。
- `cameraConstraintsJson` 和 `imageQcProfileJson` 在当前编辑流程中没有真实配置入口。
- 这些字段却被用于模板和模型兼容性门控，能够阻止项目创建。

真正有科研意义的手机型号、Camera ID、ISO、曝光时间、曝光补偿、焦距、光圈、白平衡和对焦状态，应由 Camera2/CameraX、`CameraCharacteristics` 和 EXIF 自动获取，而不是让用户创建档案。

### 3.4 载体几何与实验布局被错误拆散

当前“载体与布局库”实际上主要保存：

- 载体类型。
- 行列数。
- 位点形状。
- 微流控目标亮暗极性。

其中行列和目标极性确实被 PG-Grid 使用，所以载体数据并非完全无用。

问题在于用户真正关心的分析物、样本、标准、空白、质控和参考位点，被放到了五步实验模板向导的布局步骤中。用户需要先处理载体、设备、模型、模板发布等概念，才能看到真正的虚拟布局编辑器。

当前布局编辑器实际已经支持：

- 样本位。
- 标准位。
- 空白位。
- 阴性对照。
- 阳性对照。
- 参考位。
- 禁用位。
- 分析物分配。
- 标准浓度。
- 重复组。
- 单点、多选、整行、整列、全选和矩形选择。

所以正确方向不是重写所有布局能力，而是把它从复杂向导中释放出来，放回用户能直接找到的项目或实验方案页面。

### 3.5 版本、发布和归档过度进入普通流程

当前载体、设备、分析模型和模板普遍采用：

- 草稿。
- 发布。
- 创建新版本。
- 归档。
- 版本筛选。

这些概念适合受监管的服务器端实验室信息管理系统，不适合当前单机离线 Android 应用的普通操作流程。

项目和检测运行已经保存不可变快照，因此历史项目并不需要依赖用户保留大量可见版本。普通用户应看到“编辑、复制、删除”，而不是“创建新版本、发布、归档”。

## 4. 三种改造路径评估

### 4.1 完整回滚到 `dd643eb`

优点：

- 最快恢复旧版熟悉交互。
- 删除当前复杂资源体系。

缺点：

- 会丢失 Room 12 数据结构。
- 会丢失 PG-Grid 和 Android/Python 金标准测试。
- 会丢失比色/荧光独立光度链。
- 会丢失通用阵列结果页和科研导出。
- 会丢失大量尚未提交的新代码。

结论：不推荐。

### 4.2 保留当前架构，只修改标题和输入框

优点：改动小。

缺点：

- 无法解除模板、模型和设备的创建门槛。
- 无法修复深度学习表单与实际执行能力不一致的问题。
- 无法恢复直接编辑和删除。
- 用户仍需理解不必要的资源生命周期。

结论：不可接受。

### 4.3 功能性回退，保留微流控核心能力

做法：

- 以 `dd643eb` 的交互为参考恢复新建项目、曲线拟合、模板编辑和删除体验。
- 保留当前 PG-Grid、Room 12、光度处理、阵列结果、运行快照和导出能力。
- 后台可以暂时保留新表结构，但不再把它直接暴露给普通用户。

结论：推荐采用。

## 5. 最终产品结构

### 5.1 系统设置恢复为简单结构

普通设置只保留：

1. 应用设置。
2. 检测设置。
3. 光谱检测设置。
4. 分析物管理。
5. 试剂库管理。
6. 曲线模型库。
7. 实验模板库。

从普通设置中移除：

- 载体与布局库。
- 采集设备档案。
- 当前复杂的统一分析模型库。

内部所需的载体和设备信息由预设、项目配置和自动采集元数据提供。

### 5.2 新建项目恢复为主入口

新建项目页面建议字段：

1. 项目名称。
2. 检测模式：比色、荧光、光谱。
3. 载体类型：孔板、微流控芯片。
4. 规格：96 孔板、10×10、15×15、自定义。
5. 分析物。
6. 分析方式：自动、标准曲线、深度学习、仅信号。
7. 可选实验模板。
8. 拍摄或导入图片。

实验模板只负责快速填充，不再是创建项目的强制前置条件。

创建按钮的必要条件缩减为：

- 项目名称有效。
- 检测模式有效。
- 载体和布局有效。
- 已选择或拍摄图片。
- 当前未在提交。

没有模型时自动进入“仅信号模式”，仍然允许定位、信号提取、热力图、QC 和结果保存，但不输出伪造浓度。

### 5.3 曲线模型库恢复自动拟合

普通用户创建标准曲线只需要：

1. 模型名称。
2. 分析物。
3. 检测模式。
4. 浓度单位下拉框。
5. 标准品浓度与信号数据点，支持手动录入和 CSV 导入。
6. 点击“自动拟合”。

系统后台：

- 默认尝试适用的候选函数。
- 调用现有 `FittingEngine` 计算参数。
- 按 R²、RMSE、单调性和收敛稳定性综合排序。
- 默认推荐最佳曲线。
- 将函数和参数以只读结果形式展示。
- 保存时自动写入当前 `AnalysisModel`、`StandardCurveDefinition` 和 `CalibrationPoint` 表。

高级区域可以允许用户勾选参与拟合的函数，但不允许手动输入函数名称和参数 JSON。

### 5.4 深度学习模型暂时退出普通创建流程

当前 PG-Grid 检测没有真正接通新 `DeepLearningModelDefinition` 的推理执行器，因此：

- 暂时删除普通用户可见的“新建深度学习模型”表单。
- 当前内置模型由程序自动识别和加载。
- 页面只展示内置模型名称、用途和可用状态。

未来如果实现模型导入，应使用系统文件选择器：

- 用户只选择模型文件和模型用途。
- 程序自动复制文件。
- 自动计算 SHA-256。
- 自动读取或通过配套 manifest 获得输入尺寸、归一化和版本信息。
- 完成真实加载测试后才允许使用。

绝不要求用户手动填写 SHA、文件名、尺寸或 JSON。

### 5.5 采集参数全部自动记录

删除普通用户可见的采集设备档案及其兼容门控。

拍摄时自动保存：

- 手机制造商和型号。
- Camera ID。
- 前后摄像头与镜头类型。
- 焦距。
- 光圈。
- ISO。
- 曝光时间。
- 曝光补偿。
- 白平衡模式或增益。
- 对焦状态或焦距。
- 缩放倍率。
- 图片尺寸和方向。

固定装置、光源模块等实验室信息如果确实需要，只作为“实验装置备注”或模板中的可选说明，不参与创建项目的强制兼容性校验。

### 5.6 实验模板改为简单可复用方案

实验模板页面不再使用五步发布向导，改为一个可滚动编辑页或最多三个清晰分区：

1. 基本配置：名称、检测模式、载体和规格。
2. 分析配置：分析物、试剂、曲线模型、单位和范围。
3. 虚拟布局：位点角色和分析物分配。

操作只保留：

- 新建。
- 编辑。
- 复制。
- 删除。

不再向普通用户显示：

- 草稿。
- 发布。
- 归档。
- 创建新版本。

历史项目继续读取创建时保存的快照，因此编辑模板不会修改历史结果。

### 5.7 虚拟布局编辑器成为核心功能

保留并改造当前 `TemplateArrayLayoutEditor`：

- 10×10、15×15、96 孔板和自定义行列使用同一编辑器。
- 点击或拖动可批量涂抹位点角色。
- 支持单点、多选、矩形、整行、整列、全选和清除。
- 支持样本、标准、空白、质控、阳性对照、阴性对照、参考和禁用。
- 支持分析物、浓度、重复组和默认样本编号。
- 大阵列支持缩放和平移。

自定义非矩形规则阵列先使用“矩形边界网格 + 禁用无效位点”表达。

真正完全自由坐标的芯片只有在存在真实实验需求和对应定位算法时再实现，避免再次过度设计。

### 5.8 删除与编辑规则

用户界面统一使用“编辑”和“删除”。

编辑：

- 直接更新当前模板、曲线或布局。
- 不自动创建新版本。
- 历史项目依靠快照保持不变。

删除：

- 未被使用的数据，确认后物理删除。
- 正被当前模板引用的数据，删除前列出受影响模板数量。
- 用户确认后解除引用或一并删除相关未运行模板。
- 已完成历史项目只保留快照，不因资源删除而损坏。

数据库内部如果因外键约束必须暂时保留隐藏记录，可以使用内部墓碑状态，但普通用户不应看到“归档”概念。

## 8. 数据层处理策略

第一阶段不降级 Room 数据库，也不删除新表，先完成用户流程恢复：

- 模板中的 `analysisModelId` 改为可选业务语义。
- 项目允许模型为空并进入仅信号模式。
- 移除采集设备档案的创建门槛。
- 不再要求模型和模板处于发布态。
- 普通编辑改为原记录更新。

第二阶段在所有流程稳定后再评估 Room 13 清理：

- 删除或废弃无实际用途的设备说明字段。
- 简化状态和版本字段。
- 合并重复的旧 `CurveModel` 与新 `AnalysisModel` 使用路径。
- 为删除操作补齐事务和引用影响检查。

不要为了界面简化立即回滚数据库版本，否则会给历史数据带来更高风险。

## 9. 推荐实施顺序

### 阶段 0：保护当前工作区

- 创建安全分支或工作树快照。
- 保存当前全部修改和未跟踪文件清单。
- 禁止使用破坏性 Git 命令。

### 阶段 1：先解除项目创建阻断

- 恢复直接新建项目主页面。
- 模板改为可选。
- 移除采集档案和已发布模型的强制门槛。
- 增加仅信号模式。
- 跑通 96 孔板、10×10、15×15 三条创建和检测路径。

### 阶段 2：重做曲线模型

- 浓度单位下拉。
- 数字输入过滤。
- 标定点表格和 CSV 导入。
- 自动拟合和最佳曲线推荐。
- 删除参数 JSON 输入。
- 暂时下线不可执行的深度学习模型创建表单。

### 阶段 3：合并载体与实验布局

- 移除独立载体库入口。
- 将载体预设和虚拟布局放入项目与模板页面。
- 增加拖动涂抹和非矩形禁用位点。

### 阶段 4：删除采集设备档案

- 移除普通设置入口和模板兼容门控。
- 扩充相机自动元数据采集。
- 将固定装置和光学模块降级为可选实验备注。

### 阶段 5：恢复直接编辑和删除

- 移除创建新版本、发布和归档操作。
- 实现引用影响检查和确认删除。
- 确保历史项目快照不受影响。

### 阶段 6：数据清理与全面回归

- 评估 Room 13 简化迁移。
- 清理废弃页面和字符串。
- 更新 README。
- 执行 JVM、Room、Compose、PG-Grid 和 API 35 仪器测试。
- 进行真实用户从新建项目到结果导出的完整验收。

## 10. 验收标准

修改完成后必须满足：

- 新用户不进入设置也能成功创建项目。
- 没有实验模板也能创建项目。
- 没有定量模型也能完成仅信号检测。
- 用户不需要输入 JSON、SHA、模型尺寸或处理器信息。
- 用户不需要创建采集设备档案。
- ISO、曝光、焦距和光圈等尽可能自动记录。
- 10×10、15×15、96 孔板和自定义规则阵列使用统一布局编辑器。
- 模板、模型和布局都可以直接编辑和删除。
- 历史项目在模板或模型被编辑、删除后仍然可以正常查看。
- PG-Grid、比色/荧光分流、阵列结果和科研导出功能不退化。

## 11. 最终决定

本项目不执行完整 Git 回滚，而执行“用户体验功能性回退”：

> 恢复旧版直接新建、自动拟合、虚拟布局、直接编辑和删除的操作方式；保留当前已经验证有效的微流控定位、模态光度、Room 12、结果展示和科研导出能力。

这是风险最低、最符合现有用户习惯，也最能保住已完成算法工作的方案。
