# FluoColor 微流控与多模态检测整体重构设计

- 日期：2026-07-19
- 状态：待用户审阅
- 适用项目：`F:\Code\Android\FluoColor`
- Android 微流控算法金标准参考：`D:\A-lunwen\8多模态手机方案\pg_grid_remote_check`

上述 Python 工程不是一般性背景材料，而是 Android 微流控定位、逐单元定量、QC 输出和回归测试的行为基线。Android 实现必须先冻结其输入输出契约，再通过同图逐字段对比证明移植一致性；不允许脱离已实现代码重新发明另一套不兼容流程。

## 1. 设计结论

本次重构采用“实验方案模板优先、项目保存不可变快照、检测运行版本化”的总体架构，并以微流控芯片作为比色和荧光检测的主要目标载体。

核心决策如下：

1. 正常检测必须先选择实验方案模板，再创建项目；“无模板研究项目”作为高级入口保留，但不是主流程。
2. 实验载体、检测模态和读出布局相互独立，不设置全局“孔板/微流控”切换开关。
3. 微流控常用规格为 10×10 和 15×15；4×4 在数据层完整支持，但在普通界面中作为旧规格默认隐藏。
4. 一个模板可以在同一芯片上配置多个分析物、试剂、模型、标准品、空白和质控位点。
5. 比色和荧光共享芯片定位、透视校正和网格几何，但从光度提取开始使用不同的处理器、质量控制和分析模型。
6. 原始定量图与显示增强图完全分离，任何 CLAHE、通道增强、伪彩色或锐化结果不得直接参与科学定量。
7. 标准曲线不是单纯兜底，而是与深度学习模型并列的正式分析模型类型。
8. 当前比色和荧光只采集反应后的终点图，不加入反应前后双图模式；标准曲线和智能模型均以终点图的校正信号为输入。
9. 模板、分析模型和采集设备档案发布后不可原地修改科学参数，修改时创建新版本；历史项目始终读取创建时快照。
10. 所有关键配置缺失或不兼容时必须明确阻止定量，禁止静默应用第一个模板、静默覆盖参数或静默回退通用浓度模型。
11. 微流控定位以 `pg_grid_remote_check` 的 PG-Grid 物理先验晶格算法为主干；现有 YOLO＋霍夫圆保留为旧孔板兼容能力，不作为微流控主定位器。

## 2. 目标与非目标

### 2.1 目标

- 将现有面向不超过 96 孔板的流程升级为同时适配孔板和规则微流控阵列的通用检测系统。
- 在 Android 端支持 10×10、15×15 及后台兼容的 4×4 阵列。
- 建立模板驱动的项目创建、采集、定位、质量控制、定量、结果、历史和导出闭环。
- 真正区分比色、荧光和光谱三种检测模态，同时复用可复用的公共能力。
- 支持同一芯片多分析物，并确保不同单位、可靠范围和分析模型不会相互混用。
- 保留旧项目、旧曲线和旧孔板数据的可查看能力，避免破坏已有科研留档。

### 2.2 非目标

- 当前设计不实现反应前后双图或动力学多时间点采集，也不为未验证需求预建用户界面和数据库流程；未来只有实验数据证明终点图不足时才单独立项。
- 第一阶段不实现孔板或微流控芯片的逐位点光谱采集，但数据模型不得阻止未来扩展。
- 第一阶段不引入大型端侧分割模型作为主链路；微流控定位以 Python 工程中已验证的规则晶格算法为基础。
- 不要求普通用户理解或手动填写相机距离、滤光片中心波长、传感器增益等工程参数。
- 不对无验证数据的模型自动宣称通用性，不将“深度学习”作为跳过物理校正和实验对照的理由。

## 3. 当前实现的主要问题

### 3.1 模板和项目关系倒置

- `ExperimentTemplate.kt` 只能关联一个分析物和一个曲线模型，无法表达同一芯片多个分析物。
- `ExperimentTemplateViewModel.kt` 的布局仅保存 `Map<Int, String>`，缺少行列、分析物、标准浓度、重复组和方向信息。
- `ProjectViewModel.kt` 创建项目时将模板外键设为 `null`，导致模板无法在采集前约束项目。
- `WellLayoutViewModel.kt` 在检测后选择模板，并存在自动应用第一个模板的隐藏行为。

### 3.2 孔板语义和固定尺寸仍遍布代码

- `DetectionSettingsScreen.kt` 仍限制行数乘列数不超过 96。
- `CreateExperimentTemplateScreen.kt` 的规格按钮仍以 4、6、8、12 行和 6、8、12 列为主。
- `WellLayoutComponents.kt`、`WellMappingUtils.kt`、`ModifiedCards.kt` 中仍存在固定 8×12、8 行或 12 列映射。

### 3.3 比色和荧光仅做轻量分支

- 两种模式共同调用 `PixelExtractionUtils.extractAllPixelValues()`，均从同一圆形 ROI 提取相同的 RGB、HSV、Lab 等特征。
- 比色模式对每个裁切图执行灰世界白平衡，可能削弱真实显色差异。
- 荧光模式减去固定黑电平并放大绿色通道，处理后的值仍进入同一浓度推理路径。
- `DetectionModeSupport.kt` 声明了模式专用模型路径，但当前 assets 中只有通用浓度模型，实际会回退到相同模型。

### 3.4 曲线模型缺少适用条件

当前 `CurveModel` 只保存函数、像素类型、参数、指标和数据点，未保存分析物、检测模态、终点特征定义、光度处理版本、载体、采集设备、可靠范围、LOD、LOQ 和发布版本，无法判断一条曲线能否用于当前项目。

### 3.5 Python 微流控参考实现已经具备可复用能力

`pg_grid_remote_check` 当前测试为 42 项全部通过，已经实现：

- `pg_grid.py`：芯片区域提议、透视矫正、暗方块/亮点候选、规则轴选择、局部中心精修、Tukey-IRLS 单应晶格平差、候选支撑率、逐点置信度、来源和标志。
- `pg_quant.py`：中心 ROI、环形局部背景、自参照平场校正、颜色/强度特征、SNR、饱和和逐单元可靠性。
- `pg_quant_viz.py`：强度热力图、SNR 热力图、校正颜色图和不可靠位点叠加。
- `pg_benchmark.py`：固定种子的旋转、透视、模糊、噪声、光照和遮挡扰动基准以及新旧版本 A/B 对比。
- `pg_grid_eval.py` 和标注工具：定位误差、按 pitch 归一化指标和人工金标修订。

Android 端应复用这些算法思想、数据字段、原因码和测试语料，但不直接逐行复制 Python。移植前先形成 PG-Grid V2.1 契约：

- 将单一 `grid_size` 拆为独立 `rows`、`columns`。
- 将亮/暗目标极性从网格规格中解耦，改由载体档案显式配置。
- 定位可以使用矫正图，科学光度必须回到原始定量图采样。
- 合并几何和光度的 `confidence/source/flags/reasons/suggestions`。
- 明确分离 `signalDetectable` 与 `qualityReliable`。
- 冻结 JSON schema、字段单位、坐标系和容差，再开始 Android 移植。

## 4. 核心领域概念

### 4.1 实验载体 `CarrierProfile`

实验载体只描述承载样品的物理对象：

- `PLATE`：孔板。
- `MICROFLUIDIC_CHIP`：微流控芯片。
- `CUSTOM`：其他自定义载体。

载体档案保存名称、行列数、位点形状、方向标记、ROI 几何、定位参数版本和启用状态。10×10、15×15 标记为常用；4×4 标记为旧规格并默认隐藏，但不删除数据和算法支持。

### 4.2 检测模态 `DetectionMode`

- `COLORIMETRIC`：比色。
- `FLUORESCENCE`：荧光。
- `SPECTRUM`：光谱。

检测模态与载体正交。孔板和微流控芯片都可以关联任一检测模态，只要存在兼容的采集方案和分析模型。

### 4.3 读出布局 `ReadoutLayout`

- `GRID_SITES`：规则阵列位点，当前比色和荧光主流程使用。
- `SPECTRAL_TRACKS`：一至十条光谱轨道，当前光谱流程使用。
- `SINGLE_REGION`：单一区域读出。
- `PER_SITE_SPECTRUM`：逐位点光谱，仅保留数据枚举，第一阶段不提供创建界面。

“光谱通道”属于读出布局，不是独立载体，因此不会排除孔板或微流控芯片的光谱扩展能力。

### 4.4 终点图采集规则

当前比色和荧光项目只采集反应完成后的终点图。模板负责约束反应时间、采集设备、终点图质量、空白/质控位和分析模型，不提供反应前图、前后差分或动力学序列选项。

标准曲线和智能模型都必须声明终点信号的特征定义、处理器版本、参考策略和采集设备兼容范围。模型类型不会改变“单张终点图定量”的当前产品规则。

## 5. 信息架构与用户角色

### 5.1 普通实验人员

普通用户只需要：

1. 选择实验方案。
2. 填写项目、批次和样本信息。
3. 按引导放置芯片并拍摄。
4. 处理必要的重拍或人工确认提示。
5. 查看、导出和归档结果。

普通用户不直接编辑底层曝光、ISO、模型参数、定位阈值和滤光片波长。

### 5.2 实验室管理员

管理员负责：

- 管理分析物、试剂、载体、采集设备、分析模型和实验方案。
- 发布模板和模型新版本。
- 建立设备校准档案和模型适用范围。
- 查看高级诊断、迁移和算法版本信息。

### 5.3 高级研究模式

高级入口允许创建无模板研究项目，但必须在采集前补齐载体、模态、读出布局、分析物和采集设备。研究项目成功后可以保存为模板草稿，经过管理员检查后发布。

## 6. 新建项目与完整检测流程

### 6.1 正常流程

```text
选择已发布实验方案
→ 创建项目并写入模板快照
→ 填写项目、批次、操作者和实际试剂批号
→ 将真实样本编号映射到模板样本位
→ 检查采集设备和芯片规格
→ 按模板采集要求拍摄终点图
→ 芯片定位和帧级 QC
→ 必要时核对方向或低置信位点
→ 模态专用光度处理和位点级 QC
→ 兼容性检查后执行分析模型
→ 显示、历史、导出和归档
```

### 6.2 模板切换规则

- 首次拍摄前允许自由切换模板，切换后重新生成项目草稿配置。
- 拍摄后但尚未分析时，只允许切换到检测模态、载体几何、采集设备和终点特征完全兼容的模板；切换后创建新的配置修订并重新执行 QC。
- 已产生结果后禁止修改原检测运行的模板；重新分析必须创建新的 `DetectionRun`，改变载体或终点输入定义时应复制项目。
- 历史检测运行始终读取运行时快照，不读取模板库中的最新版本。

### 6.3 样本映射

模板定义位点角色和分析物，项目只填写真实样本和批次数据。样本映射支持顺序填充、批量粘贴、扫码和手动调整。

同一芯片多分析物时，位点必须明确保存 `analyteId`。不同分析物的空白位点默认只校正本分析物；只有模板显式声明 `GLOBAL` 时才允许作为整片公共参考。

## 7. 实验方案模板设计

### 7.1 生命周期

- `DRAFT`：草稿，可编辑，不供普通项目使用。
- `PUBLISHED`：已发布，科学参数不可原地修改。
- `ARCHIVED`：已归档，不用于新项目，但历史项目继续可读。

编辑已发布模板时创建新版本。被项目使用过的模板禁止物理删除。

### 7.2 模板创建向导

1. 基本信息：名称、用途、版本说明。
2. 检测定义：检测模态和读出布局。
3. 载体：10×10、15×15、孔板；“更多规格”中提供 4×4 旧规格和自定义行列。
4. 采集设备：绑定命名后的采集设备档案。
5. 分析物：配置多个分析物、试剂和分析模型。
6. 位点布局：配置样本、标准品、空白、阴性质控、阳性质控、参考位和禁用位。
7. 拍摄与 QC：显示用户拍摄说明，绑定 QC 档案。
8. 发布检查：检查模型兼容性、布局冲突、缺失对照、单位和可靠范围。

### 7.3 布局编辑器

- 主要快捷规格为 10×10、15×15。
- 4×4 位于“更多规格/旧规格”。
- 支持自定义行列，但必须由载体档案定义，模板不能临时修改已发布载体几何。
- 支持矩形框选、整行/整列分配、复制粘贴、重复组生成和标准浓度梯度生成。
- 位点统一使用中性名称 `R01C01`；孔板界面可以额外显示 `A1` 别名。

## 9. 采集设备档案

### 9.1 普通用户看到的内容

- 设备名称。
- 当前手机和相机是否兼容。
- 光源或光学模块状态。
- 固定装置或芯片卡槽说明。
- 相机控制策略。
- 是否需要设备校准。

### 9.2 管理员配置内容

- 支持的检测模态和载体。
- 手机型号和 Camera ID 匹配规则。
- 照明/光学模块名称及编号。
- 固定装置编号。
- 相机控制策略：自动并锁定、模板约束、固定参数。
- 允许的曝光、ISO、白平衡和对焦策略范围。
- 芯片在画面中的预期尺寸比例、最大倾角和最大透视变形。

### 9.3 自动记录内容

每次采集自动保存设备型号、Camera ID、分辨率、实际曝光、ISO、焦距、可获得的对焦信息、白平衡状态、图像旋转、芯片占画面比例和 QC 指标。

### 9.4 拍摄距离和安装方向

- 有固定装置时只保存装置编号，距离由物理结构保证。
- 无固定装置时使用芯片画面占比引导“靠近/远离”，不让用户输入厘米距离。
- 芯片方向由载体方向标记定义，APP 自动识别和旋转；无法识别时让用户在图中确认标记位置，不输入角度数值。

## 10. 数据模型

### 10.1 新增或升级实体

#### `CarrierProfile`

- 名称、物理类型、行列、位点形状。
- 方向标记、ROI 配置、定位算法配置。
- 常用/旧规格/归档状态和版本。

#### `AcquisitionProfile`

- 名称、支持模态、兼容载体。
- 设备匹配规则、照明/光学模块、固定装置。
- 相机控制策略和图像 QC 范围。
- 版本和状态。

#### `ExperimentTemplate`

- 名称、版本、状态。
- `carrierProfileId`、`detectionMode`、`readoutLayout`、`acquisitionProfileId`。
- QC 档案和算法版本。

#### `TemplateAnalyteConfig`

- 模板、分析物、试剂定义和分析模型。
- 单位、模型可靠范围和显示规则。

#### `TemplateSiteAssignment`

- 行、列、分析物、位点角色。
- 标准浓度、重复组、默认样本槽和参考范围。

#### `AnalysisModel`

- 模型类型、分析物、检测模态和终点输入特征。
- 输入特征定义、处理器版本、兼容载体和设备。
- 单位、可靠范围、验证指标、版本和状态。

#### `StandardCurveDefinition`

- 拟合函数、参数、单调方向、反算规则、LOD 和 LOQ。

#### `CalibrationPoint`

- 浓度、信号、重复编号、批次和是否被排除。

#### `DeepLearningModelDefinition`

- 模型文件、校验值、输入尺寸、终点输入定义、归一化、训练数据版本。

### 10.2 项目和检测运行

`Project` 增加：

- 模板 ID、模板版本。
- 不可变 `templateSnapshotJson`。
- 项目覆盖差异 `overrideJson`。
- 项目和样本批次信息。

`DetectionRun` 增加：

- 有效配置快照。
- 原始终点图和派生显示图引用。
- 实际采集元数据。
- 定位、光度、模型和 QC 版本。
- 帧级 QC、位点级 QC 和配置偏离记录。

数据库短期保留 `WellResult` 表名以降低迁移风险，领域层和新 UI 使用 `DetectionSiteResult` 适配模型。模式专用信号结果放入新的 `SiteMeasurement`，通过运行 ID 和位点索引关联，不强制一次性重写所有旧查询。

## 11. 配置优先级与锁定规则

有效配置按以下顺序解析：

```text
项目显式覆盖
> 项目创建时的模板快照
> 系统工作偏好
> 程序内置安全默认值
```

每个有效参数必须能输出值、来源、模板原值、覆盖原因、操作者和时间。

以下参数为关键锁定项：检测模态、载体几何、位点分析物映射、采集设备、处理器版本和分析模型终点特征定义。拍摄后改变关键锁定项必须创建新配置修订或新检测运行。

实际相机元数据属于观测值，不覆盖计划配置；结果页应显示计划值与实际值的差异。

## 12. 图像与算法架构

### 12.1 公共几何层

比色和荧光共用：

- 芯片区域提议。
- 透视矫正和规则晶格求解。
- 10×10、15×15 及兼容 4×4 坐标输出。
- 候选支撑率、几何 RMSE、位置来源和置信度。
- 原图坐标和矫正图坐标之间的变换。

定位在适合几何处理的矫正图上完成，光度定量回到原始定量图采样，避免插值改变颜色和强度。目标是暗结构还是亮结构由载体定位配置决定，不能由网格规格或检测模态推断。

孔板和微流控并不是两套完全割裂的定位系统。两者统一实现 `ArrayLocator` 接口，共用区域、方向、透视、晶格单应平差、行列编号和 QC 输出；差异只位于“如何从图像中提取局部候选”：圆孔使用圆形候选提取器，微流控使用暗方块、亮点或载体定义的候选提取器。所有候选最终进入同一个低自由度晶格求解器。

#### 12.1.1 微流控定位算法分层

微流控使用四级定位策略，按确定性和成本从低到高执行：

1. **物理标记快路径**：如果以后能在芯片外壳或卡槽加入 ArUco/AprilTag 类方向标记，优先用标记直接得到四角、方向和单应矩阵。这一方式成本最低、可解释性最高，但不作为当前硬件的强制要求。
2. **PG-Grid 主路径**：使用 `detect_chip_region → fit_grid_points → bundle_adjust_lattice` 对规则阵列求解。候选只提供图像证据，最终坐标由低自由度晶格模型约束，并输出候选支撑率、逐点置信度和外推标志。
3. **轻量学习兜底**：只有芯片区域或四角提议失败时才调用轻量分割/关键点模型，模型输出仍必须进入 PG-Grid 晶格平差和候选支撑校验，不能直接把神经网络结果当作最终位点。
4. **失败与人工确认**：学习兜底仍无法满足几何和证据阈值时，要求重拍或人工确认方向/四角，不静默生成规则均分网格。

#### 12.1.2 孔板和微流控的候选提取策略

- 圆形孔板使用 `CircularSiteCandidateExtractor`。短期由现有 YOLO 粗检测＋霍夫圆局部中心提供候选，随后进入公共晶格平差；中期可以在不改变上层业务的前提下替换候选提取器。
- 微流控使用 `MicrofluidicSiteCandidateExtractor`，参考 PG-Grid 的黑帽暗方块、顶帽亮点、局部组件和旋转感知规则轴拟合。
- 霍夫圆只负责圆形候选，不用于方形、亮点或其他微流控单元。
- 现有 YOLO 模型可以暂时承担旧孔板粗检测或芯片区域提议，但微流控不再依赖逐位点目标检测框。
- 不直接把 YOLOv8 替换为更高版本并宣称完成升级。任何模型替换都必须在固定金标集上比较定位误差、失败率、端侧时延、内存和功耗。

#### 12.1.3 现代端侧模型候选

- **YOLO26n-pose/segment**：2026 年的 YOLO26 提供端到端 NMS-free 推理和面向边缘部署的轻量头。若后续积累了芯片四角或掩膜标注，可训练小模型只预测芯片区域、四角和方向，不预测 100/225 个位点。
- **EdgeSAM**：适合零样本或少样本的芯片区域分割兜底，论文报告其在 iPhone 14 上可超过 30 FPS；Android 端仍需以真实设备基准决定是否纳入安装包。
- **EfficientViT-SAM/MobileSAM**：作为区域提议备选，不进入逐单元主链路；只有 A/B 基准证明其显著减少重拍，才允许默认启用。

学习模型部署不再新增 PyTorch Mobile 技术债。新增模型优先评估 ExecuTorch、LiteRT 或 NCNN；具体运行时由同一参考手机上的模型兼容性、时延和包体积基准决定。

### 12.2 原始定量图与显示图

- `QuantitativeImage`：未经显示增强，用于科学计算。
- `PreviewImage`：允许对比度增强、伪彩色和标注，只用于用户观察。

数据库和导出必须标明结果来自哪一种图像及处理版本。显示增强不得写回定量图。

### 12.3 比色处理器

处理顺序：

```text
整图参考校正
→ sRGB/设备响应线性化
→ 光照场校正
→ 中心 ROI 与局部背景采样
→ 比色特征
→ 比色 QC
```

要求：

- 禁止逐位点灰世界白平衡参与定量。
- 优先使用芯片或装置上的白/灰参考、空白位点或设备校正矩阵。
- 输出原始和校正 RGB、Lab、相对空白差值、ΔE2000、通道比值和满足线性化前提的光密度 OD。
- Hue 仅在饱和度达到可靠阈值时允许用于模型。
- 比色 QC 包含参考有效性、偏色、光照均匀度、阴影、高光和通道饱和。

### 12.4 荧光处理器

处理顺序：

```text
暗背景校正
→ 荧光平场校正
→ 中心 ROI 与局部环形背景采样
→ 净强度、积分强度和 SNR
→ 荧光 QC
```

要求：

- 当前固定黑电平和绿色通道增强仅可用于预览，不用于定量。
- 优先级为设备暗场、芯片空白位点、局部环形背景和全图稳健背景。
- 输出原始强度、暗背景、局部背景、校正强度、积分强度、有效发光面积、背景噪声、SNR 和饱和比例。
- 未完成传感器线性标定前，不跨不同曝光直接用 JPEG 像素除以曝光时间和 ISO。
- 荧光 QC 包含背景过高、低 SNR、饱和、热点、坏点、激发光泄漏和平场异常。

### 12.5 光谱处理器

保留现有轨道分离、波长标定、质量评分、寻峰、FWHM、峰面积和 SNR 链路。光谱的载体、读出布局、采集设备和分析模型通过模板绑定，现有一至十轨道对应 `SPECTRAL_TRACKS`。

### 12.6 统一接口

公共接口输出：

- 原始信号、校正信号、主特征。
- 背景、SNR、置信度和质量标志。
- `signalDetectable`：是否检测到信号。
- `qualityReliable`：该信号是否满足可靠定量要求。
- 处理器名称和版本。

检测到信号但质量不可靠时，只显示信号和原因，不输出具有误导性的浓度。

## 13. 分析模型库

### 13.1 页面结构

“曲线模型库”升级为“分析模型库”，内部提供两个主要分类：

- 标准曲线。
- 智能模型。

标准曲线可以作为正式主方法、验证基线或兼容兜底；智能模型只有在验证充分且终点输入特征匹配时才能作为主方法。

### 13.2 兼容性检查

运行前必须检查：

- 分析物。
- 检测模态。
- 终点输入特征和处理器版本。
- 载体、采集设备和曝光策略。
- 单位和可靠范围。
- 模型声明的空白、质控或设备校准策略是否满足要求。

任何关键条件不满足时不输出浓度。模式专用模型不存在时不回退到通用图像浓度模型，可以保留校正信号并提示建立标准曲线或选择兼容模型。

### 13.3 标准曲线

- 标准曲线只使用反应后终点图提取的校正信号，不要求反应前图。
- 曲线必须保存主特征、参考策略、处理器版本、设备兼容范围和终点反应条件。
- 曲线可靠范围首先属于分析模型，模板只能进一步收窄，不能扩展到模型验证范围之外。
- 发布时保存标准点、重复数据、残差、R²、RMSE、LOD、LOQ、批次和排除记录。

### 13.4 智能模型

- 智能模型只接收与训练一致的终点图或终点特征。
- 当前版本拒绝导入需要反应前图、双图或时间序列输入的模型；此类能力未来需要独立设计和验证。
- 一个通用模型不得同时默认承担比色和荧光定量。
- 模型文件必须保存校验值，导入和运行时验证完整性。

## 14. 对照与终点采集

### 14.1 当前使用的三类参考

- 暗场图：主要用于荧光设备黑电平，可按设备或实验批次采集。
- 白场/平场图：用于设备光照校正，按校准周期更新。
- 空白/阴性/阳性质控位：用于当前芯片和批次的质量控制，模板应优先保留。

暗场和白场属于设备校准，不是要求用户为每个样本多拍一张未反应图；空白和质控位与样本位存在于同一张终点图中，也不会增加拍摄次数。

### 14.2 终点图是当前唯一项目图像输入

比色和荧光项目统一使用：

```text
完成实验反应
→ 拍摄一张终点图
→ 芯片/孔板定位
→ 模态专用光度校正
→ 标准曲线或智能模型定量
```

只要标准曲线或智能模型是在相同终点采集条件、设备档案和处理器版本下建立并验证，终点图已经包含浓度定量所需信息。额外拍摄反应前图会增加实验步骤、配准误差、光照漂移、曝光变化、存储和失败概率，因此当前版本明确不加入。

如果未来实验数据证明某一特定实验的终点模型无法消除个体初始本底，前后差分必须作为独立研究功能重新设计、建立新标准曲线并验证收益，不能在当前产品中预先增加未使用模式。

## 15. 结果页设计

### 15.1 页面标签

1. 芯片总览。
2. 分析物结果。
3. 原图与定位。
4. 质量控制。

### 15.2 阵列显示

- 10×10 自动适配屏幕并允许点击位点。
- 15×15 默认显示色块和状态，支持缩放和平移。
- 4×4 旧项目可以显示位点编号和数值。
- 原图页叠加预测坐标、候选支撑、外推点和无效位点。

### 15.3 多分析物热力图

- 全芯片总览使用相对可靠范围百分比或角色布局，不混用不同分析物的绝对单位。
- 单个分析物页使用该分析物自己的绝对浓度图例。
- 浓度色带与 QC 编码分离：警告用边框，失败用斜纹或禁用色，不改变浓度颜色含义。

### 15.4 位点详情

公共信息包括样本、分析物、角色、浓度、可靠范围、几何置信度、模型和算法版本。

比色详情增加原始/校正颜色、ΔE、OD、参考和反光信息；荧光详情增加原始/校正强度、背景、SNR、饱和和信号可检测状态。

## 16. 质量控制和错误处理

### 16.1 帧级 QC

- 过曝、欠曝、模糊、光照不均、倾斜、透视、候选支撑率、几何 RMSE 和外推比例。
- 每条规则输出机器码、严重级别、用户说明和可执行建议。

### 16.2 位点级 QC

- 位置外推、低 SNR、饱和、阴影、高光、热点、遮挡和模型超范围。
- 不可靠位点从聚合统计和重复组平均中排除，但保留原始结果与原因。

### 16.3 失败策略

- 配置不兼容：阻止开始。
- 帧级严重失败：要求重拍。
- 部分位点失败：允许查看其余结果，但明确排除异常位点。
- 模型不兼容或超范围：不输出浓度，保留信号。
- 15×15 大面积饱和时必须停止定量，不能用热力图掩盖不可用数据。

## 17. 历史、导出和追溯

一个项目可以包含多次 `DetectionRun`，用于重拍、重新分析或模型版本对照。新运行不覆盖旧运行。

CSV、PDF 和 ZIP 归档必须包含：

- 模板和分析模型快照。
- 载体、位点布局和多分析物映射。
- 采集设备计划配置和实际元数据。
- 项目覆盖及原因。
- 原始终点图、派生显示图和定位叠加图。
- 原始/校正信号、浓度、SNR、置信度和 QC 标志。
- 算法、处理器和模型版本。

历史结果只能使用快照重建，不能读取当前模板或模型的可变内容。

## 18. 旧数据迁移

- 旧项目默认映射为孔板载体，保留原有行列。
- 旧模板迁移为单分析物旧版模板，状态为 `ARCHIVED` 或 `LEGACY`，根据旧数据生成只读快照。
- 旧曲线迁移为标准曲线模型；无法推断的检测模态、终点特征和处理器版本标记为旧版兼容信息，不用于新模板自动匹配。
- 旧 `WellResult` 通过适配层转换为领域层 `DetectionSiteResult`。
- 旧结果页继续可读，新项目只走新流程。
- 数据库迁移必须提供 Room migration test，不允许破坏现有项目和历史导出。

## 20. 测试和验收标准

### 20.1 数据和流程

- 已发布模板和模型不可原地改变历史项目结果。
- 配置优先级、覆盖来源和锁定规则有单元测试。
- 旧数据库升级后项目、模板、曲线和历史结果仍可打开。
- 终点图采集、不兼容模型和缺失参考条件状态机有单元测试。

### 20.2 几何和算法

- 10×10、15×15 和兼容 4×4 金标准图均能输出固定数量、固定顺序的位点。
- Android 与 Python 对相同输入的坐标、信号和 QC 输出在预定义容差内一致。
- 量化使用原始定量图，显示增强不会改变保存的科学结果。
- 比色和荧光分别验证跨位置、跨光照或跨曝光的重复性，阈值由对应模型发布时的验证指标给出，而不是全局硬编码。
- 新定位模型只有同时降低金标失败率或定位误差，并满足端侧时延、内存和安装包约束时才能替换既有路径；“模型版本更新”本身不是验收标准。

### 20.3 模型和质量控制

- 模式、终点特征或设备不匹配时不得输出浓度。
- 模型超可靠范围时显示超范围状态，不外推为普通数值。
- `signalDetectable` 与 `qualityReliable` 独立测试。
- 帧级和位点级错误均提供原因码和中文建议。

### 20.4 Android 工程

- 所有 UI 使用 Jetpack Compose 和 Material 3，不新增 XML 布局。
- 所有用户可见文本进入中英文 `strings.xml`，非 Composable 回调使用提前获取的资源字符串。
- 所有提示使用项目自定义 Toast，不使用 `android.widget.Toast`。
- 图像和模型计算不在主线程执行，页面在任务开始后立即显示进度或处理中状态。
- 新增和修改的业务代码提供详细中文注释，并补充相应单元测试。

## 21. 最终业务规则摘要

1. 模板是项目上游配置，不是检测后的后置选项。
2. 载体、模态和读出布局分别建模。
3. 正常用户只选方案和拍摄，复杂参数由管理员档案和自动记录承担。
4. 比色和荧光共享几何，不共享光度校正、QC 和浓度模型。
5. 标准曲线和智能模型均必须声明完整终点输入定义和兼容范围。
6. 比色和荧光当前只采集一张反应后终点图，不加入前后双图模式。
7. 同一芯片多分析物必须使用分析物级模型、单位、图例和参考位。
8. 所有结果使用不可变快照，所有覆盖必须留痕，所有不兼容必须大声失败。
