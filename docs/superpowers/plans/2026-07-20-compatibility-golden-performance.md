# 工作包 6：旧流程兼容、金标准与性能验收实施记录

## 目标

在不破坏旧孔板科研留档的前提下，移除普通流程中的 96 位点上限和固定 8×12 映射，
并使用用户已经实现的 Python `pg_grid_remote_check` 作为 Android 微流控定位与光度的
数值基线，完成可重复执行的端侧性能、UI 和完整回归验收。

## 已实施内容

### 1. 通用尺寸与索引

- `GridLayoutPolicy` 统一载体与旧检测偏好的 `1..99` 逐维边界。
- 所有普通阵列使用 `siteIndex = row * columns + column`。
- 10×10、15×15、4×6 等非固定规格都有往返和越界测试。
- 行标签支持 `A..Z、AA..`，避免自定义阵列超过 26 行后出现非法字符。

### 2. 旧项目显式兼容

- 无模板历史项目的旧默认 `12×8` 存储方向恢复为 `8×12`。
- 新模板项目的 `12×8` 载体保持真实方向，不套用历史兼容。
- 旧布局编辑器、热力图、数值图、趋势图、手动拟合和导出均从 `wellIndex` 与项目列数
  重算坐标，不继续信任可能由固定 12 列写入的 `virtualRow/virtualCol`。
- YOLO/霍夫圆旧孔板兼容链的排序读取项目真实行数，不再包含固定 8 行/12 列警告。

### 3. PG-Quant 边界一致性修复

4×4 样例暴露出 Android 在原图采样前没有先裁剪矫正图边界：位于边缘的背景环可能被
回投影到芯片外画面。现已在 `PgQuantSampler.extractRawUnit()` 中先执行矫正域边界检查，
再做逆单应投影；裁掉的像素仍计入理想样本数，因此 `ROI_OUT_OF_BOUNDS` 与 Python 语义
保持一致。

### 4. 可重复金标准

- Python 参考测试：`42/42`。
- 参考核心 SHA-256：
  `67620a2ed5921d22f30e7f881872ad6edf6ff0fe2007849f649afb30a3577a84`。
- `export_v2_1_goldens.py` 可同时冻结后台 4×4 合成 PNG。
- `verify_v2_1_goldens.py` 严格比较文件集合和 JSON 全字段，只忽略
  `referenceMetadata.generatedAtUtc`。
- 10×10、15×15：Android/Python 坐标、来源、帧级 QC 与 PG-Quant 光度逐字段验收。
- 4×4：保留固定 16 位点、行优先顺序与冻结网格光度一致性；恢复为主规格前需使用真实
  芯片重新发布定位与 QC 门槛。

`0`。
