## 1. 结论

当前 Android 工程已经实现了可运行的 PG-Grid/PG-Quant 主链，在冻结的 10×10、
15×15 和后台兼容 4×4 合成样例上具有较好的数值一致性和端侧性能；但不能称为
“完美实现了参考目录全部内容”。

主要原因有四类：

1. Android 定位器是同一科学契约下的重新实现，不是 Python 的逐算法等价移植；规则轴选择、局部精修、单应拟合细节和候选支撑距离存在差异。
2. Android 尚未建立与 Python `pg_benchmark.py` 等价的七扰动族端侧退化曲线，现有同图一致性测试主要使用合成干净样例。
3. Python 的帧级曝光、模糊、光照均匀性等 QC 没有完整接入当前微流控协调器的重拍门控。
4. 用户界面只展示阶段文字和完成后的最终原图定位/结果热力图，没有展示矫正图、ROI/背景环、平场校正或定位中间证据。

因此准确表述应为：**核心主链已实现并通过合成金标准容差验证，但算法等价性、真实复杂场景覆盖和可视化证据链仍不完整。**

## 4. 关于“畸变矫正”的准确表述

当前微流控 PG-Grid 主链中的 `rectifyChip()` 是基于四角的 8 自由度单应变换，解决的
是平面芯片的旋转、缩放、剪切和透视视角问题。它不等于基于相机内参和畸变系数的
镜头径向/切向畸变校正。

项目旧 `ImageCorrectionViewModel` 中确实存在估计 `k1/k2` 并调用 OpenCV
`Calib3d.undistort()` 的代码，但当前直接新建项目会直接进入 `WellDetection`，微流控
网关明确绕过旧 `DetectionViewModel`；PG-Grid 协调器没有调用旧图像矫正页面。因此：

- 旧孔板链路可能展示“原图/矫正图”；
- 当前直接微流控 PG-Grid 链路没有使用或展示该径向畸变校正；
- Python V2 设计本身也明确把径向项 `k1` 暂缓，等待扰动基准证明其可辨识性。

在正式接通并验证前，微流控页面应使用“透视矫正”或“视角校正”，不应笼统宣传为
“镜头畸变矫正”。

## 6. 建议的后续优先级

### P0：补齐可追溯的处理证据链

1. 在结果页新增“处理过程”标签，而不是让高速算法为了动画被人为延迟。
2. 保存或按冻结参数重建：原图区域、透视矫正图、定位叠加、ROI/背景环、平场诊断。
3. 所有派生图明确标记“仅用于显示/诊断”，定量继续从原始图反投影采样。
4. 处理中页面使用步骤时间线和最近完成阶段的缩略图；处理过快时直接进入完整证据页。

### P0：补齐帧级图像质量门控

把曝光、欠曝、模糊、光照不均和过度透视真正接入 `GridDetectionCoordinator` 的
`RetakeRequired` 判断，不能只依赖候选支撑率和补位比例。

### P1：建立 Android 扰动退化曲线

将 Python 已有的旋转、透视、模糊、光照梯度、遮挡、高光和噪声七族确定性场景导出为
Android 测试语料；同时比较定位误差、来源分类、支撑率、光度秩相关和可靠位点比例。

### P1：处理定位实现差异

优先评估以下差异是否造成真实图回归，再决定严格移植还是保留 Android 变体：

1. 规则轴组合搜索与加权 k-means 的差异；
2. 10×10 专用方形组件精修缺失；
3. 完整两轮局部观测重采样缺失；
4. 候选支撑距离 `0.42 pitch` 与参考 `0.25 pitch` 的差异；
5. Tukey 稳健尺度下限与 DLT 参数化差异。

### P2：镜头畸变校正

在没有相机内参或可信可辨识性验证时，不建议把旧启发式 `k1/k2` 直接并入科学主链。
应先建立设备标定或确定性径向畸变基准，再决定启用相机内参校正或继续只做透视矫正。

## 8. 用户实拍兼容修复与 Android 迁移边界

### 8.1 实拍失败根因

用户提供的 2 张 10×10 与 4 张 15×15 EL 背光实拍图均为“亮背景上的暗单元”。旧 Android
直接新建逻辑却把 15×15 的 `targetPolarity` 写成 `BRIGHT`，定位器也把这个配置当作硬约束，
导致真实 15×15 图片按亮点查找时支撑率降为 0。与此同时，协调器把任何帧级 `FAILURE` 都直接
转成 `RetakeRequired`；即使 10×10 图片已经形成支撑率 `0.91/0.77` 的可信晶格，也会因曝光、
光照或透视阈值被强制退回“需要重新拍摄”。

### 8.2 已实施修复

- 定位器同时提取暗目标和亮目标候选，依次使用候选数量与理论位点数的吻合度、内部灰度均值/中位数
  提示、候选轴和稳健单应是否真正成立来裁决极性；载体旧极性只作为最终平局偏好。
- 直接新建 15×15 的兼容默认值修正为 `DARK`，避免运行快照和日志继续传播错误语义。
- 帧级 QC 继续完整持久化，但不再因为保守图像阈值隐藏已经生成的测量和热力图。真正不可计算的
  图片解码失败、定位异常或坐标契约损坏仍由异常/契约校验阻止。
- 完成页明确提示“质量风险已记录但结果已保留”，结果页可同时查看总览、分析物、原图、九步过程
  和质控原因，由用户决定是否需要重拍。

### 8.3 固定实拍回归与设备验收

六张原始 JPEG 已按字节不变方式复制到 `app/src/androidTest/assets/pg_grid/real_v1/images/`，仅将文件名
改为 ASCII；`manifest.json` 记录原始文件名、SHA-256、规格、Python 极性、支撑率和质量状态。
设备测试故意继续给 15×15 传入旧 `BRIGHT` 偏好，验证图像证据仍会覆盖旧配置。最终六张均自动
裁决为 `DARK`，Android 支撑率为 `0.91 / 0.77 / 1.0 / 1.0 / 1.0 / 0.924444`，全部形成完整可信晶格。

在 `emulator-5554` 中通过系统 Files 从 Download 导入真实 `1.jpg`，完成 15×15 生产流程：保存
`225/225` 位点，得到 `211` 个可靠结果，不再出现强制重拍页；原图定位叠加、最终晶格和九步处理过程
均可见。相关截图位于 `docs/superpowers/plans/screenshots/real-15x15-*.png`。

### 8.4 仍未完成的迁移事项

当前 Android 算法核心仍是 Kotlin + OpenCV Java API，并非 `android_migration.md` 推荐的 C++ 核心、
薄 JNI JSON 边界和 Kotlin/Compose 应用层。工程中尚无桌面 C++ parity、CMake/NDK 核心或
`libpggrid.so`；Android OpenCV 仍为 4.5.3，也未与参考端锁定到建议的 4.9+。此外，目前只实现了
单元极性自动识别，网格规格仍由项目的 `rows × columns` 提供，尚未自动并行尝试 10×10/15×15。

因此当前准确结论是：**最严重的实拍极性错误和强制重拍问题已经解决，首批真实芯片已进入固定回归；
但 C++/JNI 正式迁移、OpenCV 版本对齐、规格自动识别和多设备实验室金标准仍需作为后续独立工作包完成。**

## 9. 2026-11-20：在同一张图上比较六种定位方法（桌面研究，不是 App 新功能）

**结论：**保留 PG-Grid 为正式入口，优先移植“连通域质心＋晶格”和“行列投影”作为可切换对照。“自相关周期＋相位”在两张 PG 未达误差线的荧光难例上达标，但在本轮 6 张 EL 背光实拍原图上均拒绝输出，适合作为研究选项。均分和霍夫圆保留作几何先验/形状失配的对照，不推荐作为方形芯片默认定位。当前 Android 用户仍只能运行 PG-Grid。

### 9.1 实际跑了哪些方法

已查到本地参考工程原有 `thesis_exp_baseline_ablation.py`，它在 PG 选中的矫正图上比较均分、投影及霍夫圆；后两者失败时会返回均分网格，并非三种方法都找到了孔。本轮复用上游定位/组网函数与原有 Android 语料，增加连通域、自相关、失败记录、原图评分与实拍叠加图，不复制/修改参考仓库。

| 路线 | 本地实现与论文依据 | 主要边界 |
|---|---|---|

### 9.2 语料、协议与指标

- **50 张输入，不是 50 块独立实物。** Android 资产中有 14 张中等扰动仿真图（10×10/15×15 各 7 类）和 6 张实拍原图（2 张 10×10、4 张 15×15），另有这 6 张图的 6 张紧裁派生图。[上游 `examples/fluo`](https://github.com/xiewangzhenyan/pg_grid/tree/bc9b9efd0a7f5175eff31a6bd96c5d62891dfb94/examples/fluo) 的 24 组 15×15 荧光难例均为带生成器真值的仿真，包含棋盘、梯度、局部点亮和稀疏发光；它们是特意选出的困难回归图，不能视为真实样本发生率。核对了该提交全部 48 个图像/真值文件与本地内容（文本归一换行）。
- **自动协议 `auto`（主表）：**输入只有原图和已知规格。PG 运行自己的多区域主链；五种对照共用单区域自动检测与未压缩矫正图，用图像亮度统计提示极性（均分、霍夫不使用极性）。对照不使用 PG 最终孔坐标或真值。局部候选组装复用同一函数，因此是六条可比较的读图路线，不是六个从头独立开发的系统。
- **同图协议 `shared`（诊断）：**五种对照另用 PG 最终选中的芯片框和极性重跑，以区别前端选择与后端找孔。此处的结果/耗时**不是独立端到端定位**，不再重复记 PG；一个输入合计 11 条记录。两种协议从不使用测试真值选参数或给未知图片挑赢家。
- **判据在跑前固定：**按相同行列编号回到原图，计算欧氏中心误差除以真值网格全部水平/垂直邻边长度的中位数（一个孔距）。每图 P95 ≤ 0.20 孔距记为达标；无输出仍计分母，不能重排孔号或只比最近邻。`hit_fraction` 是该图允许误差内的位点比例，`observed` 是有直接局部候选支撑的位点数；只依赖轴线的方法该项留空。真实照片没有独立逐孔人工真值，只报是否输出、局部支撑及叠加图，不报准确率。仿真的几何达标也不是可直接定量的验收线。

## 10. 双模态芯片定位：比色三种版型与荧光的独立留出实验（2026-11-20）

**为什么另做一轮。** 第 9 节的荧光难例、常规扰动和背光实拍不能代表所有比色图。无罩比色可呈亮底暗孔，黑罩可呈暗底亮孔，半透罩中基底和显色反应都可见；暗背景荧光又可能只有半块阵列发光。共同的量是**物理孔中心与行列编号**，不是“像素一定亮/暗”。本轮只比较定位，不报告由几何分数推断的浓度精度，未修改手机端。

### 10.1 两个新候选

1. **稳定斑点拓扑网格（免外框）。** 在整幅照片的亮度和通道色差上找多阈值稳定区域（MSER），合并同一斑点的嵌套区域；从相邻点的位移估计两个方向和孔距，把连接关系转为整数行列差。考虑隔孔点亮产生的二倍周期，要求有唯一的占用窗口，应用 RANSAC 单应拟合，再由近邻观测精修。输入只有原图和已知规格，不读模态、芯片外框、是否有罩、PG 结果或真值。没匹配的内孔只标为推算。它仍假设阵列规则，且常规拍摄中的两根轴离图像水平/垂直不远（候选方向限 ±32°）；对称版图仅凭一张无标记图不能证明物理 A1 在哪一角。
2. **双路证据复核。** 保留 PG 的“先找面板”路线和以上“先找孔”路线，用同一批高对比候选比较中心吻合、四边支持及网格外是否还多出一行候选。两路在孔号上明显分歧（P90 位移 >0.45 孔距）且得分差 <0.12，或证据不足，就拒绝给正式网格；CSV 保存实际选择的 `pg`、`graph` 或 `rejected`。这里的得分不是概率，两路也不是统计独立的金标准。亮度增强和色差仅服务定位，不进入荧光净强度或比色读数。

方法来源：[Matas 等，MSER](https://doi.org/10.1016/j.imavis.2004.02.006) 是通用极值区域检测；[Shu 等，标定板拓扑组网](https://doi.org/10.1007/s00138-009-0202-2) 用角点和 Delaunay 拓扑恢复编号；[Fischler 与 Bolles，RANSAC](https://doi.org/10.1145/358669.358692) 是抗离群几何估计。本实现是基于斑点和整数邻接的新组合，不是照搬上述论文，也没有声称这些论文验证过本芯片。应用背景可参见 [Hou 等的手机比色/荧光双模态实拍](https://doi.org/10.1186/s11671-017-2078-9)：该系统依靠夹具及不同光路读两类试条，并非本项目的方孔阵列。

对比色微流控本身，[Baek 等，2020](https://doi.org/10.3390/bios10110187) 的手机纸基微流控装置包含 24 个反应区、8 条微通道，是按物理位置读多个显色区的实物例证；其孔数、材料和版图与这里不同，不能借用其测定结果证明本定位器的精度。

### 10.2 留出设计与结果

开发时仅用本地已有 `seed=11` 的 9 张示例（无罩/黑罩比色及荧光，各 3 档难度）、已知荧光棋盘例及两张无标注实拍看失效模式。锁定几何算法及复核参数后，用[同一提交的公开成像模型](https://github.com/xiewangzhenyan/pg_grid/tree/bc9b9efd0a7f5175eff31a6bd96c5d62891dfb94)新生成 48 张有真值的 1200×1200 终点图：4 种光路/版型 × 10/15 两种孔数 × 理想/典型/困难三档 × 两个新基础种子（7321、14891）。面板占视野比例、孔尺寸、倾斜方向和角度随种子变化；黑罩/半透罩透过率分别为 0.002/0.20。孔距判据、渲染配置及种子生成规则见脚本；同种子在不同版型之间有意复用，无训练或按真值选赢家。**这 48 张是同一家族仿真器的留出，不是 48 块独立实物或外部验证。**

### 10.3 实拍分歧与负对照

- **6 张 EL 背光实拍无逐孔人工真值。** PG、连通域及新拓扑各输出 6/6，双路只输出 5/6，并且这 5 张均保留 PG。被拒绝的 [10×10 实拍](pg-grid-comparison-20261120/multimodal/real_10x10_01.jpg) 中，PG 和拓扑各自都标了 97/100 个有局部支撑的孔，然而按同一编号比较，拓扑相对 PG 的有符号中位位移约 **−1.00 行**，中位欧氏差为 0.985 孔距。上缘重复结构可能被当作一行孔，匹配数量不能决定谁的行号正确。
- **真实照片的几何一致性实验（不是准确率）。** 对六张图施加一个事先给定的小透视变换，比较原输出经该变换后的位置与新图输出的同名孔，P95 ≤0.20 孔距且两次均有输出才算一致。PG 5/6，拓扑 5/6，双路 4/6，连通域 0/6；同错一行也可能表现稳定，不能用这些数字替代实拍真值。双路除上述拒绝外，还在另一张 10×10 的变换前后出现约 1.125 孔距的 P95 差异。
- **无芯片对照（不是零浓度板）。** 全黑、全白及 3 张独立生成的纯像素噪声中，新拓扑会在其中 2 张噪声上误拼网格；双路 5/5 均拒绝。PG 在该协议下返回 5 张几何结果，但其原生 `trusted` 均为假。该检查只用来验证拒绝语义，不是误检率的总体估计。
- **下一步：**优先让用户在同一原图核对“PG／稳定斑点拓扑／双路复核”，先取得独立、带方向编号的实拍标注（比色与荧光各自取样），再考虑改默认。若可改夹具，给结构参考帧加非对称已知标记是更直接的错行解决方案：[Park 等，2022，手机比色对齐参考卡](https://doi.org/10.1021/acsomega.2c00793)、[Zhang 等，2023，带 ID 的 ArUco 与单应配准](https://doi.org/10.1371/journal.pone.0287099)。暗场荧光下黑白标记可能不可见，可固定芯片先拍结构图，再确认无位移或重新配准；移动后的两张图绝不能直接拷贝孔坐标。没有实际标记的现有芯片不计为已支持此方法。

- **OpenCV** 是相机标定用的有序圆点阵列检测器，和只做霍夫圆不一样。[官方接口](https://github.com/opencv/opencv/blob/4.13.0/modules/calib3d/include/opencv2/calib3d.hpp)要求全阵列点数及排序均成功。本次用 `SimpleBlobDetector`，关闭圆度/凸度/惯性形状过滤以适配方孔；单一极性先试对称阵列，未成功再试官方聚类标志；同时试正/反灰度，只有两个结果均成网时才按孔与间隙亮度差择优。编号只按图像上/左方向规范化，不代表识别实体 A1。在本批无罩和荧光图上是**未输出完整网格**，不是计算出了误差为零的孔位。
- **pyphe** 使用 [Kamrad 等，eLife 2020](https://doi.org/10.7554/eLife.55160) 的 [0.983 作者发行版](https://pypi.org/project/pyphe/0.983/)自动布网模块，行列投影、峰距截尾估计与余弦网格拟合均为原作者代码。其任务是规则菌落阵列，不是 CEA 专用工具；本轮只比较网格坐标，没有宣称运行它的全部菌落分割/面积测量流水线。原图几乎一半是背景时，强行铺满阵列并不可靠；受益于外部自动矫正，得分从 0 提高到 22。矫正后的 47 个输出中有 25 个超线，不能只报输出数。
- **预处理公平性：**原图最大边 960 px；另一路由同一参考库的 `detect_chip_region` 自动选首个面板并透视矫正，两个第三方算法共享它。拒绝中央兜底框；不向外部算法提供 PG 胜出的面板、目标真值四角或坐标。两组成绩都报告，不能看完真值逐图取两者的最好结果。

## 12. 传统方法对照：连通域质心＋坐标 K-means（2026-11-21，桌面）

**结论：值得作为可选的传统基线，不宜替代默认自动定位。** 孔都清楚时，先找候选再用 K-means 分行列，连方孔也能编对；缺行或出现额外反光时，恰好凑出规定的行数，不代表孔号正确。早期 Android 微流控用过固定 K 的**加权**坐标聚类，整数格错位是改用规则轴筛选的原因之一（见第 7 节）。这次比较的是通用的**等权** K-means++ 初始化版本，不是旧版重跑，也没有改变手机菜单、光度处理、标定或历史记录。

### 12.1 聚类对象与文献

- **聚坐标＝给孔编号。** 先用芯片外框做透视矫正，再提取孔的候选质心并校正残余旋转。对 15×15 阵列，横坐标分 15 簇、纵坐标分 15 簇，各自排序后按行列交叉编号；缺局部观测的交点只记“推算”。这不同于把整张照片硬分成 225 类。无方向标记的对称阵列也不能仅靠聚类恢复芯片真实的 A1 朝向。
- **聚像素＝分孔与背景。** [Belean 等（2015）](https://doi.org/10.1186/s12859-015-0842-3)先对荧光微阵列布网，再用 K-means 分每个斑点与局部背景。这支持把像素聚类作为分割选项，不表示较亮簇一定是孔、是 CEA 信号，或能给整张芯片编号。
- **相关布网先例。** [Larese、Bayá 与 Gómez（2006），§2–3](https://sedici.unlp.edu.ar/handle/10915/22453)用连通域质心、空间约束 K-means 与 Voronoi 图划分 cDNA 图像上的不同子阵列；它支持在阵列几何上用聚类，但任务并非本项目的单芯片逐孔行列恢复。[Arthur 与 Vassilvitskii（2007）](https://theory.stanford.edu/~sergei/papers/kMeansPP-soda.pdf)是本次所用 K-means++ 初始化的算法来源，不提供缺行恢复或物理孔号保证。

### 12.2 同图、同候选的结果

沿用第 10 节相同的 48 张留出仿真图及图像级判据：按**同一孔号**比较原图中心，逐图误差的 P95 ≤0.20 个真值孔距为达标，未输出仍在分母内。两条连通域路线共用外框、透视矫正、亮暗极性、局部去背景、Otsu、质心和残余旋转估计；只换行列组装方法。两者均至少需要 `4 × 边上孔数` 个候选，用预测网格中位孔距的 0.32 倍作同一匹配门限，每格最多接受一个候选。K-means 的每个候选等权、每轴种子 37、10 次初始化，以簇内平方误差选解；没有按测试真值挑初始化或方法。

| 留出图 | 坐标 K-means 达标 | 同候选规则晶格达标 | PG-Grid 达标 | 斑点拓扑达标 | K-means 未输出 |
|---|---:|---:|---:|---:|---:|
| 无罩比色 | 0/12 | 0/12 | 4/12 | 10/12 | 5 |
| 黑罩比色 | 10/12 | 8/12 | 9/12 | 11/12 | 0 |
| 半透罩比色 | 11/12 | 11/12 | 10/12 | 12/12 | 0 |
| 荧光 | 0/12 | 1/12 | 9/12 | 10/12 | 10 |
| **合计** | **21/48** | **20/48** | **32/48** | **43/48** | **15** |

前两列是严格的同候选对照；后两列是第 10 节同图、各用自己前端的整套定位器。K-means 有 12 张给了网格但误差超线，同候选规则晶格有 5 张；只统计成功返回的图或只数界面上的圆点，会掩盖这种差异。**荧光 0/12 并不等于 K-means 不能处理荧光**：这批有 10 张未形成网格，在另计的 24 张既有荧光挑战图上则有 4 张达标、10 张有输出但超线、10 张未输出。

### 13.1 图片来自哪里，传给算法的是什么

- **第一批 48 张生成图**是第 10、12 节已有的同图对照，基础种子 7321、14891；复用已有照片及指纹，没有把旧图冒充新数据。**第二批 48 张**是在固定本轮定位函数、参数和判据之后，用新种子 29033、51769 重新渲染的。两批各为四种光路/版型 × 10×10、15×15 × 三档难度 × 两个种子，各有 **7,800 个带行列号的孔中心**。两批 JPEG 没有相同的字节指纹，但来自同一仿真器，跨版型还共享部分随机条件，不是 96 块独立实物。传统方法不需要训练，这里使用生成数据来**测试**而非学习。

## 14. GenePix Pro：定位、取值与质控调研（2026-11-22）

### 14.1 定位：先摆网格，再逐点找边界

`F:/Android_dev/GenePix Pro` 提供 v7.3 用户手册、v7 软件资料表和 4300A/4400A 扫描仪资料表，没有安装包、程序或源码。本轮核对[官方用户手册（0112-0178 D）](https://www.moleculardevices.com/sites/default/files/en/assets/user-guide/br/genepix-pro-microarray-acquisition-and-analysis-software.pdf)、[官方软件资料表](https://www.moleculardevices.com/sites/default/files/en/assets/data-sheets/br/genepix-pro-7-software.pdf)及[脚本参考（5000552 B）](https://www.moleculardevices.com/sites/default/files/en/assets/user-guide/br/genepix-pro-software.pdf)，没有运行 GenePix。可确认的是产品流程、公开参数和输出语义，不是专有算法的源码或逐步等价实现。

1. **布局先验。** `GAL` 文件或手工建立的布局定义子阵列、行列和点位身份；`Block / Column / Row / ID / Name` 对应的是实验设计，不是由荧光亮度推断的身份（手册第 13–15、55–57 页）。
2. **整阵 → 子阵列 → 单点。** `Find Array` 粗放整阵，`Find All Blocks` 找各子阵列，`Align Features` 在已有格点附近对齐单点。资料表说明全局对齐处理平移、旋转和倾斜；单点支持圆、方和基于边缘检测的不规则区域，可限制尺寸或关闭自动改尺寸。手册记录低于 6 个像素、尺寸越界、与邻点重叠等 `Not Found` 条件；用户可复核及微调。这里的像素数和尺寸约束是扫描场景参数，不能作为手机通用门槛（手册第 22、61–66 页；脚本参考第 78、82–86 页）。公开资料未给出整阵匹配的目标函数或完整点位检测器，不能写成 GenePix 使用了 K-means、DBSCAN、霍夫圆或 PG-Grid。

### 14.2 取值：独立保存前景、背景和质量证据

- **先定区域，再做统计。** 在原始单波长图上算前景均值、中位数和标准差，默认用局部背景中位数扣除。局部背景默认取同心、直径为斑点直径 3 倍的区域，剔除本点、相邻点及近边界隔离区；尺寸和隔离宽度可调。还有全局、阴性对照和形态学背景可选，并记录背景离散程度、超过背景阈值的像素比例等。原始像素、预览增强、背景扣除和双波长比值不是一回事（手册第 18–26、30–31、70 页）。这不支持把中心单像素、最亮五点或固定整列平均当成默认取值。
- **公开文件复算。** [Bioconductor `pepDat` 的 GPR 样例](https://raw.githubusercontent.com/bioc/pepDat/0dd86467efdd314c15ea49bc11855afeebebbdad/inst/extdata/gpr_samples/f1_1.gpr)（SHA-256 `32c032b35775d89e7355b6d72a95b94694d8e1fc376748eda79e29e9446f53bc`）有 5808 行、41 列，背景为 `LocalFeature`。逐行验证 `B635` 等于 `B635 Median`，`F635 Median - B635`、`F635 Mean - B635` 均与导出列完全一致。第一点的净中位数为 `3861−93=3768`；SNR 则是 `(3622−123)/130≈26.915`，用前景均值、背景均值和背景标准差，不是净中位数除以背景噪声。该点 `Total Intensity=434608` 接近原始前景均值乘像素数 `3622×120=434640`，而不是净均值乘像素数 `3529×120=423480`，不能将该列直接当作 FluoColor 的净积分强度。该复算不验证图像分割或孔中心准确率。
- **没找到不等于空孔或没有信号。** `Not Found` 是局部对齐失败，`Absent` 是布局未指派，`Bad` 是质量标记；GPR 保留位点 ID、坐标、前景、背景、饱和和标记等，而不只是一个浓度或均值。`GAL / GPS / GPR` 分别用于布局、分析与采集等设置、逐点结果；可以借鉴其分工，不必引入专用文件格式（手册第 26、29–30、65–73、79 页）。

| --- | --- |
| 先把定位和测量质量分开 | `GridDetectionCoordinator` 已有透视晶格及随后按形状分割；固定 96 孔板已有圆心、内径和 A1 校正。保留现有算法、手动四角和 A1 确认；优先在同一确认页点孔查看「实测／推算／人工」来源、实际采样区、背景区和过曝提示。对于荧光暗孔，用已确认的孔壁或格点确定编号，局部证据不足就标记，不因孔不亮而整行挪位；也不把估计格点当作找到了真实孔缘。 |
| 验证背景环和荧光检出 | `PgQuantSampler` 已按孔距设背景环并排除本孔，但没用所有邻孔的实际掩膜逐像素排除邻孔。对密排、方孔和局部错位测试邻孔屏蔽、边界留白及最小有效背景像素数。背景不够时标记，不悄悄改用另一种背景。`FluorescencePhotometryProcessor` 目前以净强度绝对值计算 SNR，用于检出判定；在预期亮于背景的荧光上，强负差也可能被判成「可检出」。应独立验证净值方向、背景噪声接近零和真实阴性场景，保留有符号原值并区分低读数、背景异常和成像失败；不把 GenePix 的公式或阈值直接设成现有默认。 |
| 取值试验不混进几何变化 | 保留默认全孔中位数与用户选项。在同一确认网格、同一批标准品下，仅改变取值区或背景方法；比较低浓度偏差、独立质控回算误差、重复孔 CV 和有效孔数。孔内中心较亮与板面中心一带较亮是两个问题：前者比较固定中心区与全孔统计，后者用相同曝光下分布在中心和边缘的等浓度参照验证照明差异；扣背景不等于已校正激发增益。多孔仍按同一样本、分析物和重复组统计，不按整列或最亮孔取样；改取值／背景方案须匹配曲线版本或重标定。 |
| 统一可追溯输出 | 复用 CSV/ZIP 和已保存运行的证据，不另做研究页面。逐孔保留物理孔号、原图坐标、前景/背景和有效像素数、主特征、质控及定位来源；同图对照再保存算法、版本、失败状态和叠加图。显示摘要不牺牲明细，已冻结的历史不重算。 |

### 14.4 已发表的 GenePix 对照与复验设计

- **直接相关的先例。** [Yang 等（2022，*Chemosensors* 10(8):330）](https://pmc.ncbi.nlm.nih.gov/articles/PMC9447405/)用同一批商业扫描仪图像对比 Android 蛋白微阵列读数和 GenePix Pro 7。其[作者公开实现](https://github.com/ygsaber/Fluorescent_Array_Sensor/blob/4b46e4686d19b9fdb03c725321ee08d6c512fb26/app/src/main/java/com/sunshine/Fluorescent_Array_Sensor/GetDotIntensity.java#L9)要求先输入行列，把图幅等分，再对每一格做灰度 Otsu、分别统计前景/背景均值和中位数，并计算扣背景的前景积分。论文图 5 的六组 Spearman 相关系数均超过 0.95，但两边分析的是扫描仪采集的图，不证明手机拍摄下的定位精度、读数一致性或浓度准确度。可用其公开方法作为已裁正图的分孔/读数参考，不能冒充 GenePix 的定位算法，也不能与未经裁正、未给布局的找孔法混算。此次核对论文与源码，未运行该 App。
- **固定两类验收。** 定位在独立人工标注的同一批原图上测同编号中心误差（用孔距归一化）、整行/列错号及未输出；有无参考图或人工初始化分开统计。读数在相同已确认几何和同一份成像输入上逐一比较掩膜、孔内统计和背景改动，用独立标准/质控检查回算偏差和重复性，并记录失效孔；不要以两种软件的高相关系数代替一致性。若有许可版 GenePix 和兼容 TIFF，可增加同输入、同初始布局的商用软件对照，记录版本、设置和 GPR；GPR 仍不是标注真值。
- **对照边界。** [4300A/4400A](https://www.moleculardevices.com/sites/default/files/en/assets/data-sheets/br/genepix-4300a-and-4400a-microarray-scanner.pdf)使用 PMT、专用滤光和 16 位 TIFF；手机有透视和相机处理，不能直接沿用其像素、饱和、SNR 阈值及双波长比值。比色仍走颜色/参考光密度链，只共享几何、采样证据及质控工作流。相关实证见 [Ritchie 等（2007）背景扣除比较](https://doi.org/10.1093/bioinformatics/btm412)和 [Skandarajah 等（2014）手机定量成像](https://doi.org/10.1371/journal.pone.0096906)。论文可运行的定位基线继续使用第 11–13 节的公开方法；GenePix 目前只作为商用工作流参考。
